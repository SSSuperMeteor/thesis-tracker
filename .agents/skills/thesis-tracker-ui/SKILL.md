# thesis-tracker 界面设计

与通用技能 frontend-design 冲突时,以本文件为准。frontend-design 用来检查成品有没有滑向"模板化默认",本文件决定具体怎么做。

## 产品与受众

- 一个人在自己电脑上用的研究工作台。Windows + Chrome,中文界面,只在本机打开。
- 三件核心事:看数据库里有什么;读建议卡并追溯每个数字的来源;手动发起分析并看进度。
- 气质:冷静、克制,像排版认真的研究笔记本,不像交易 App。数字是主角,不靠装饰撑场面。
- 不是营销页。不要 hero 大标题、不要渐变、不要插画。

## 唯一的记忆点:论点与证据并排

建议卡详情页分两栏:左栏是阅读栏(判断、理由、失效条件),右栏是证据面板(事实表,吸顶)。

- 理由和说明文字里的每个事实数字是一个"事实标记":1px 虚线下划线,强调色。悬停显示来源(工具、日期、fact_id 前 8 位);点击后右栏对应行高亮约 1.2 秒并滚入视野。
- 这是全站唯一的强调手法和唯一的非用户触发动效。其余地方保持安静。
- 前端不解析数字。后端以片段数组提供正文:`{"type":"text","value":"…"}` 与 `{"type":"fact","fact_id":"…","display":"333.69 美元/股"}`。前端只负责把片段渲染成文本和事实标记。

## 设计令牌

先把这些写成 CSS 变量,所有颜色、间距、圆角都引用变量,页面里不出现裸色值。

```css
:root {
  color-scheme: light dark;
  --bg: #F3F5F6;        /* 冷灰纸面,不是米色 */
  --surface: #FFFFFF;
  --surface-2: #EAEFF1;
  --ink: #17212B;
  --ink-2: #4F5B67;     /* 辅助文字,不得再引入更浅的文字色 */
  --rule: #D5DDE2;
  --accent: #0E6E7E;    /* 链接、选中、焦点、事实标记 */
  --accent-soft: #D9ECEF;
  --ok: #2F7D5B;
  --warn: #96590A;
  --bad: #B03A2E;
  --none: #98A3AD;      /* 仅用于装饰性的"缺失"空心标记,不用于文字 */
  --r-ctl: 4px;         /* 按钮、输入框 */
  --r-panel: 8px;       /* 面板、对话框 */
  --space: 4px;         /* 间距用 4 的倍数 */
}
@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0F1519; --surface: #151D23; --surface-2: #1B252C;
    --ink: #E4EAEE; --ink-2: #A3B0BB; --rule: #27333C;
    --accent: #5FB8C8; --accent-soft: #17353C;
    --ok: #5FBE95; --warn: #E0A64E; --bad: #E57A6D; --none: #5B6873;
  }
}
```

- 不用红绿表示涨跌。A 股和美股的红绿约定相反,色盲也分不清,所以涨跌只用符号(+ / −)和文字,不上色。
- 状态永远是"文字加形状",不靠颜色单独表达:正常(实心点加文字)、过期(时钟图标加文字,警告色)、出错(叉号加文字)、缺失(空心虚线框)。
- 阴影只用于对话框;其余层次用 1px 线和背景色阶表达。不用渐变。
- 圆角分级:单元格 0,控件 4px,面板和对话框 8px。不要所有东西同一个圆角。

## 字体与排版

- 字体栈只用系统字体,不下载网络字体(本机、离线也要能用):
  `"Segoe UI Variable Text","Segoe UI","Microsoft YaHei UI","PingFang SC","Noto Sans CJK SC",system-ui,sans-serif`
- 字号阶梯:12 / 13 / 14(正文)/ 16 / 20 / 28(页面标题)。字重只用 400 和 600。中文标题不要 700。
- 行高:阅读文字 1.65,表格 1.4。字距保持 0。
- 阅读栏宽度上限约 38 个汉字;表格不受此限。
- 所有数字列用 `font-variant-numeric: tabular-nums`,表格中数字右对齐,单位跟在数字后面,字号小一级、颜色 `--ink-2`。
- 标题和标签用句式大小写,不用全大写,不在标题上方加小标签,不用 "A · B · C" 式的圆点串,不在按钮文字后加 "→"。

## 布局

```
┌────────────┬────────────────────────────────────────────┐
│ Thesis     │ 页面标题                      价格至 10-02  │
│ Tracker    ├────────────────────────────────────────────┤
│ 总览       │                                            │
│ 公司       │            内容区(最宽 1280)              │
│ 建议卡     │                                            │
│ 任务    ●1 │                                            │
└────────────┴────────────────────────────────────────────┘
```

- 左侧导航 200px,窗口窄于 900px 时变成顶部栏。导航里"任务"旁的小点表示有任务在运行,文字同步提供数量。
- 总览:一张覆盖表格,首列(公司)左侧吸附,表头吸顶,横向可滚动。
- 公司页:顶部公司代码和价格状态;下面分"财报""价格""可算的财务指标""建议卡"四段,不用标签页。
- 建议卡详情:两栏(见上)。窄屏时证据面板移到正文下方,不再吸顶。
- 对齐:正文左对齐;数字列右对齐;不使用居中和两端对齐。

## 组件规则

覆盖表格
- 行是公司,列按"财期截止日所在的日历季度"分组。不同公司财年不同,界面和文案里不得出现"第几财季",只显示真实的财期截止日。
- 单元格 24×24:10-K 显示 K,10-Q 显示 Q,修订申报在角上加一个小点,缺失显示虚线空框。悬停显示表单、财期截止日、披露日、accession。
- 年份只在每年第一列的表头写一次,季度字母小号;每年之间用 1px 竖线分隔。
- 表尾列:价格数据范围、最新价格日、建议卡数量。

价位带(建议卡里)
- 一条细横轴,按顺序标出止损、买点区间、收盘价、目标。标记的横向位置由后端以百分比提供,前端只摆放,不计算价格。数值标签直接写在标记旁。
- 观望、减仓、回避没有价位时不画价位带,写"此动作没有价位"。

按钮与对话框
- 每个视图最多一个主按钮(实心强调色),其余用描边按钮。
- 会花钱的操作必须弹确认框:写明"将调用 DeepSeek 并按量计费",并显示后端提供的最近几次分析平均用量。不要在前端写死任何金额或 token 数。
- 动作命名全程一致:按钮"生成建议卡",进度"正在生成建议卡",完成提示"建议卡已生成"。

任务进度
- 逐步列表:轮次、每次工具调用(名称、参数、字节数)、token 用量与预算。进度区域设 `aria-live="polite"`。
- 不做假进度条。不知道总量时只显示已完成的步骤。

价格过期提示
- 数据落后超过阈值时,在页面顶部显示一条提示:最新价格日、需要运行的命令 `uv run prices-ingest`(需运行两次),并提供"复制命令"按钮。界面不执行任何命令。

## 数字与来源(硬性规则)

- 前端不计算、不四舍五入、不拼单位。所有金融数字和标签都是后端给的字符串,前端原样渲染。
- 前端代码里不得出现 `toFixed`、`toLocaleString`、`Intl.NumberFormat`、百分比乘法等数字格式化逻辑,也不得出现硬编码的金融数字。有测试扫描这一点。
- 公司代码和 fact_id 加 `translate="no"`。
- 日期原样显示后端字符串。

## 状态与文案

- 空状态是行动入口:"还没有这家公司的建议卡。选择周期后点击生成建议卡。"
- 加载:静态灰块占位,不做闪烁动画。
- 错误:说清发生了什么和怎么处理,不道歉,不含糊。例:"价格数据已过期(最新 2026-10-02)。在终端运行 uv run prices-ingest,需要运行两次。"
- 拒绝的草稿要展示违规规则编号和大白话说明,不隐藏。
- 每张卡底部固定显示免责声明(由后端提供原文,不得删改),并安静地列出提示词版本和校验器版本。
- 语气:中文、平实动词、不用感叹号、不写营销词。

## 动效

- 只有三处:事实标记点击后的高亮、对话框打开、任务状态变化时的文字更新。
- 不做进入动画、不做悬停上浮、不做滚动视差。
- 尊重 `prefers-reduced-motion`:开启时高亮改为静态底色。
- 只对 `transform` 和 `opacity` 做过渡,不写 `transition: all`。

## 无障碍与质量底线

- 用语义元素:`button` 做操作,`a` 做跳转,`table` 加 `th scope`,不用带点击事件的 `div`。
- 所有交互元素有可见焦点:`:focus-visible`,2px 强调色环,偏移 2px。不写没有替代的 `outline: none`。
- `<html lang="zh-CN">`,提供跳到主内容的链接,标题层级连续。
- 图标按钮要有 `aria-label`;装饰图标 `aria-hidden="true"`。
- 文字对比度 ≥ 4.5:1,控件边界和焦点环 ≥ 3:1。需要写一个脚本读取令牌并断言所有文字与背景组合,浅色和深色两套都要过。
- 页面宽度从 360px 到 1920px 都不出现整页横向滚动;宽表格在自己的容器里滚动。
- 不加载任何外部资源(无 CDN、无网络字体、无统计脚本);响应头设置 `Content-Security-Policy: default-src 'self'`。

## 交付前自查

- 回看设计令牌:是否滑向通用默认(米色加陶土色、近黑加荧光绿、满屏圆角卡片加灰阴影、满处大写小标签)。如果有,改掉并在报告里说明。
- 借香奈儿的话:出门前照镜子,摘掉一件配饰。找出一个纯装饰、不承载信息的元素并删掉。
- 如果环境里已有无头浏览器,分别在 1440×900 和 390×844、浅色和深色下对总览、公司页、建议卡详情截图自查;没有就如实标注"视觉未验证",不要自行安装系统级软件。
